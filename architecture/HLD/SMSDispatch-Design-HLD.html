Azure WAF
Web Application Firewall sits in front of all inbound traffic. Blocks malicious requests before they reach the API.
OWASP rule sets (SQL injection, XSS, …)
DDoS protection
Geo-blocking & IP allow-listing
⚠️ Best practice — skipped in Azure free tier. Azure WAF requires Azure Front Door (Standard/Premium) or Application Gateway (WAF v2 SKU), neither of which is available on the free tier. Configure this in production to protect against OWASP Top 10 threats.
Azure Front Door / App Gateway
🔀
Azure API Management
API Gateway layer between the WAF and the ASP.NET Core Web API. Centralises cross-cutting concerns.
Rate limiting & throttling per client
Auth — API Key / OAuth 2.0
Routes filtered traffic → Web API backend
Request/response transformation & logging
⚠️ Best practice — not configured in Azure free tier. Azure API Management has no free tier (Consumption tier has minimal free calls; Developer/Standard tiers are paid). In this project the Web API is called directly. Enable APIM in production for centralised rate limiting, auth policies, and API versioning.

③ Azure Service Bus
📡
Topic: sms-dispatch
Pub/sub fan-out. SmsPoller publishes BusMessage JSON when message status becomes Queued. Topic-based design makes it easy to add consumers without changing producers.
send-processor → SmsSender ✅ implemented
audit-logger → SmsAuditLogger [NOT IMPL] — shows scalability
Scalable pub/sub pattern
☠️
Dead-Letter Queue (DLQ)
Auto-moves messages after MaxDeliveryCount exceeded. One DLQ per subscription. DeadLetterHandler drains it and updates status → DeadLettered.
send-processor/$deadletterqueue
MaxDeliveryCount = 5 (configurable)
④ Azure Functions
🔍
SmsPoller
Timer-triggered. Queries SQL for Pending messages, marks them Queued, publishes BusMessage to Service Bus topic.
Schedule: 0 */1 * * * *
Requires AzureWebJobsStorage

Triggered by send-processor subscription. Sets status → Sending, calls ISmsApiClient, updates to Sent or Failed.
